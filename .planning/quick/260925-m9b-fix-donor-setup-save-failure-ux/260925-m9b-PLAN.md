# Quick Task 260925-m9b: Fix donor-setup save failure UX

## Problem

Reported on iOS and Android PWA: on the donor profile form, the first tap of
"Save & continue" grants location permission and then appears to do nothing.
A second tap succeeds after ~3s and lands on the Thank You screen. Tapping the
Home tab then shows a stale "Something went wrong" dialog.

Root causes established by reading the code and the project's Supabase logs:

1. `writeError` is App-level state, but the `AlertDialog` that renders it only
   exists inside the `home` and `profile` render branches. A failed write on
   `donor-setup`, `donor-thankyou` or `create-request` sets the state with no
   dialog mounted, so the failure is invisible and resurfaces later on Home.
2. `DonorProfileSetup.requestLocationAndSave` sets `geoPhase` back to `"idle"`
   before calling `onSave`, and never awaits it. The spinner disappears and the
   button re-enables while two upserts and a select are still in flight, which
   is what prompts the user to tap again.
3. The write-error dialog's "Retry" button is wired to `setWriteError(null)` —
   identical to "Dismiss". It never retries.
4. `handleSaveDonor` / `handlePosted` destructure `{ error }` from the Supabase
   call. A thrown `TypeError` from `fetch` (the actual failure here — Supabase
   edge logs show no request at all for the first attempt) escapes entirely.
5. The failure `console.error` calls are guarded by `import.meta.env.DEV`, so in
   the installed PWA build there is no diagnostic trace at all.

## Tasks

### Task 1 — Make write failures visible on every screen, and make Retry retry

Files: `src/App.tsx`

- Extend `writeError` state with an optional `retry: () => void`.
- Extract the screen branch chain into a `renderScreen()` closure and return
  `<>{renderScreen()}{globalOverlays}</>` so the write-error dialog and the push
  pre-permission dialog mount above every screen.
- Delete the duplicated dialogs from the `home` and `profile` branches.
- Confirm button re-invokes `writeError.retry` when present; when absent (the
  duplicate-request case, which is not retryable) render a single Dismiss button.

Verify: `npm run build` passes; grep shows exactly one `open={writeError !== null}`.
Done: a failed save on `donor-setup` shows the dialog immediately.

### Task 2 — Hold the saving state through the DB write

Files: `src/screens/DonorProfileSetup.tsx`, `src/App.tsx`

- Add a `"saving"` phase to `GeoPhase`; keep the overlay up and the CTA disabled
  for both `requesting` and `saving`, with distinct copy per phase (EN + MY).
- Change `onSave` to `(profile: DonorProfile) => Promise<boolean>` and await it.
  Reset to `"idle"` only on failure — on success the screen unmounts with the
  spinner still up, so there is no interactive gap.
- `handleSaveDonor` returns `true`/`false` accordingly.

Verify: `npm run build` passes.
Done: the CTA cannot be double-tapped while a save is in flight.

### Task 3 — Catch thrown fetch errors and always log write failures

Files: `src/App.tsx`

- Wrap the Supabase writes in `handleSaveDonor` and `handlePosted` in
  `try/catch` so a thrown `TypeError: Load failed` surfaces the dialog instead
  of rejecting the handler's promise.
- Drop the `import.meta.env.DEV` guard from write-failure `console.error` calls
  so production PWA builds keep the breadcrumb.

Verify: `npm run build` and `npm run lint` pass.
Done: a network-layer failure produces both a visible dialog and a console error.
