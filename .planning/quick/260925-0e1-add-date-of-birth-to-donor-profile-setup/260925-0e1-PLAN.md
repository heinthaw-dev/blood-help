# Quick Task 260925-0e1 — Date of birth on donor profile setup

Add a date-of-birth field to the donor profile setup form and persist it on
`public.profiles`. The picker is three native `<select>` dropdowns (Day / Month /
Year) so a donor never has to scroll a calendar back thirty years from today.

## Locked decisions (from the user)

| Decision | Choice |
|---|---|
| Picker UX | 3 native dropdowns: Day / Month / Year, Burmese month names + Burmese numerals when `lang === 'my'` |
| Required | Yes — Save disabled until a complete, valid DOB is entered |
| Age gate | Under 18 blocks saving, with a bilingual inline message |
| Storage | `public.profiles.date_of_birth` (identity data, next to name/phone) |
| Elsewhere | Not displayed on any other screen this task |

## Assumption stated (deviation from "NOT NULL")

The column is **nullable** at the DB level, not `NOT NULL`:

- `App.tsx:580` upserts a `profiles` row with only `id` + `phone` at OTP verification,
  before donor setup ever runs. A `NOT NULL` column breaks that insert for every new user.
- Requesters who never become donors have a `profiles` row and no DOB to give.
- 15 existing rows already have no DOB, so the migration itself could not add `NOT NULL`.

"Required" is therefore enforced in the donor form (Save stays disabled), and the DB
enforces the *age rule* on whatever value does arrive:
`CHECK (date_of_birth IS NULL OR date_of_birth <= current_date - 18 years)`.
That constraint is dump-safe — a row that passes today passes forever, since people
only get older.

## Tasks

### Task 1 — Migration: `profiles.date_of_birth`

- **files:** `supabase/migrations/<ts>_profiles_date_of_birth.sql`
- **action:** `ALTER TABLE public.profiles ADD COLUMN date_of_birth date`, plus a named
  CHECK constraint enforcing 18+ and a `>= 1900-01-01` sanity floor. Apply via
  `mcp__supabase__apply_migration`. No RLS change needed — existing owner-scoped
  policies on `profiles` already cover the new column.
- **verify:** `list_tables` shows the column; inserting a 2012 DOB is rejected.
- **done:** column + constraint live on the remote project, migration file in repo.

### Task 2 — `DateOfBirthPicker` component

- **files:** `src/components/DateOfBirthPicker.tsx` (new)
- **action:** Three native `<select>` elements in a 3-column grid, styled from the
  existing field tokens (`--border-field`, `--radius-input`, `--focus-ring`,
  `--color-primary-wash`) so it matches `Input` at 52px tall. Burmese month names and
  Burmese numerals via `formatNumber` when `lang === 'my'`. Day list clamps to the
  selected month's length (Feb/leap years). Value is an ISO `YYYY-MM-DD` string or
  `null` while incomplete. Year range spans the last 100 years.
- **verify:** `npm run build` type-checks; picking 31 then switching to February
  clears the impossible day.
- **done:** component exports named + default, matching project convention.

### Task 3 — Wire into the form and the write path

- **files:** `src/screens/DonorProfileSetup.tsx`, `src/App.tsx`
- **action:** Add `dateOfBirth: string` to the `DonorProfile` interface; render the
  picker between Name and Blood type with a bilingual label + hint; extend
  `saveDisabled` to require a complete DOB with age >= 18; show an inline under-18
  message. In `handleSaveDonor`, include `date_of_birth: profile.dateOfBirth` in the
  `profiles` upsert.
- **verify:** `npm run build` and `npm run lint` clean; manual pass through donor setup.
- **done:** a saved donor has `date_of_birth` populated on their `profiles` row.

### Task 4 — Regenerate types

- **files:** `src/types/database.ts`
- **action:** Regenerate via `mcp__supabase__generate_typescript_types` so
  `profiles.Row/Insert/Update` carry `date_of_birth`.
- **verify:** `npm run build` passes with the upsert typed, not cast.
- **done:** types match the live schema.

## Out of scope

- Prefilling DOB when re-opening the form. The form does not prefill name or blood type
  today either; adding prefill means changing the `hydrate-user` edge function, which is
  a separate change.
- Showing age anywhere in the UI.
- Any change to `callable_donors_for_request` — DOB must not leak to requesters.
